# Building a host adapter

Begin with a new source checkout generated by `tools/new-port.py`. The existing game builds stay independent. `adapters/stub/adapter.hpp` documents an engine-neutral C++ interface; it is deliberately inactive and not a native mod loader. Your adapter can be C++, C#, Lua or another language supported by the target. The JSON/shared-memory contracts, not an engine-specific binary, are the integration boundary.

## Inspect the host

Record the owned game build, engine, graphics API/bitness, mod loader and available camera/player/physics/damage APIs in `adapters/<game>/port.json`. Search existing GitHub implementations first; inspect and pin code, dependencies and licenses before reuse. Do not import whole older game ports to obtain one camera hook. If supported APIs are absent, record the extra native investigation needed rather than declaring universal compatibility.

Game executable identities and signature/offset checks belong in the adapter. Fail closed for unknown builds. Menu, loading, death, cutscene, alt-tab and disconnect behavior must be defined for the host. Use permitted single-player modding paths; do not develop an anti-cheat bypass.

## Prove the shared foundation first

Build the guest and renderer, run the mock host, and use `frame_probe` to confirm coherent captures and echoed camera frames. That validates the shared layer independently of a game. This does not validate a graphics API's renderer behavior. Load the add-on through the game's appropriate ReShade route and verify the technique compiles and draws.

## Align the camera

Convert positions to Minecraft block units, +Y up; yaw0 faces +Z, positive pitch looks down. Send camera position separately from player feet and convert vertical FOV explicitly. Do not assume another game's scale, near plane, Z sign or frame timing. Compare a stationary block through turns, translations and FOV changes. The exporter publishes the exact capture pose with each complete image. Advanced captured-pose synchronization/reprojection is not implemented by this minimal renderer; a high-latency port may need it.

Stop pose messages when the host is not in a playable scene, or send `ctl:false` while maintaining a camera preview. The guest's pose lease is 500ms. Forward held item actions and hotbar changes only when the host grants control. The adapter must handle native weapon conflicts and release its own controls on transition; the guest cannot disable a host gun by itself. Minecraft inventory cursor/drag/text forwarding is not in the minimal core; add it explicitly if required, including host cursor/focus rules.

## Add interaction as capabilities

`block_changed` observes Minecraft mutations. It does not create native collision, identify a native surface for placement, or replay a whole scene after reconnect. Add initial block snapshots, host collision sampling and native colliders as an adapter capability; test placement, standing, jumping, walking off, mining, scene changes and reconnect separately.

For each item, define its Minecraft event, units, native action, owning thread and acknowledgment. Decide which engine owns the outcome before writing damage or healing. Preserve true item use/consumption, cooldowns and native enemy rules. Add generic event producers to the guest only when the semantics are independent of a game; native damage formulas stay in the adapter. This starter does not include working cross-game sword damage, fireworks, pearls, shield/totem damage handling or potion effects. Its ordinary Minecraft items still behave normally inside Minecraft.

Native state changes usually belong on a game thread. Queue work from network/render callbacks. Do not call a game's physics or damage methods from an arbitrary WebSocket callback.

## Calibrate and package

Host depth uses a separate, verified conversion. The shader offers `HostPlanes`, `HostReversedZ` and disabled-by-default `DepthGate`; these values must use the same distance units as Minecraft. Nonstandard/logarithmic/infinite-far depth requires an adapted shader, not guessed constants. Test walls both in front of and behind blocks. Baseline uploads are synchronous and intentionally conservative; measure frame time before adopting another port's graphics-API optimization.

Record tested vs unimplemented capabilities in the port report. Supply an installer scoped to that game and isolated Minecraft profile, preserve existing configs/saves, and verify a clean install. Never bundle purchased game files, account databases or developer worlds. Do not describe an untested port or a built DLL as playable.
